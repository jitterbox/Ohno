# Work plan — August 2026 upgrade pass

Companion to [RESEARCH-2026-08.md](RESEARCH-2026-08.md). Baseline is
`master` @ `6a8e397` (v0.1.2). **No code has been changed yet.**

## Ground rules

1. The nine intentional patterns in RESEARCH §4 are **not** in scope.
   Where a phase touches one, it says so and justifies it.
2. Every existing assertion stays green:
   `LeetCodeBenchTests` (24), `SpacePatternTests` (24+),
   `CardinalityGapTests` (15), `EdgeCaseTortureTests` (31),
   `AcceptanceTests`, `RecursionAndLinqTests`, `AlgebraTests`,
   `PatternApproachTests`, `SelectionAnalysisTests`,
   `ServerProtocolTests`, `CompilationContextTests`,
   `ProjectWorkspaceTests`, and the extension Vitest suite.
   A phase that *intends* to change an expectation must change it in the
   same commit, with the reason in the commit message.
3. Honesty rule from the README is the tie-breaker: when a change could
   make a bound tighter or looser without proof, it goes looser.
4. One phase per commit, each independently revertable.

`Ohno.Complexity.slnx`, which **the .NET 8 SDK cannot parse** (RESEARCH
§1.1). The declared CI toolchain (`8.0.x`) and the toolchain CI actually

- extension — **44 tests green** after the probe-path change

  `ComplexityAnalyzer.Server`, `Microsoft.CodeAnalysis.Workspaces.MSBuild.dll`,

## Phase 1 — Accuracy: the BCL cost model (S1)

Fixes RESEARCH §3.1 and §3.2. This is the highest-value phase.

### 1.0 The governing rule (decided)

> **O(1) is never a fallback. It must be positively known.**
> An unresolved executable operation costs `C(symbol)` at Low
> confidence. A provably constant-time language/runtime primitive is
> constant *because it is on an allowlist*, not because nothing else
> matched.

This is broader than the `IsSystemPrimitive` bug that surfaced it, and
the audit of every site that currently invents O(1) is part of 1.1.

### 1.1 Remove every O(1) fallback for unresolved executable work

| Site | Today | After |
|---|---|---|
| `Calls.cs:98` `IsSystemPrimitive` — any non-collection `System.*`/`Microsoft.*` type | `Cx.One`, Medium | allowlist hit → `Cx.One` High; otherwise `C(name)` Low + a warning naming the member |
| `Calls.cs:93` `IsNoCostPrimitive` — `GetHashCode`/`Equals`/`ToString` by **name** | `Cx.One`, High | keyed by *(type, member)*: `int.GetHashCode` is O(1), `string.GetHashCode`/`Equals`/`ToString` are O(len). Name-only matching is exactly the "not positively known" case |
| `CSharpMethodAnalyzer.cs:108` — method symbol with no body | `ComposedCost.Unit(…)` = O(1) | `C(name)` Low unless cataloged or allowlisted |
| `Calls.cs` `AnalyzeCreation` — uncataloged metadata constructor | `ComposedCost.Unit("alloc", …)` = O(1) | `C(.ctor)` Low unless cataloged or allowlisted |
| `Operations.cs:306` `AnalyzePropertyRead` — metadata getter, no syntax | falls through to children ⇒ O(1) | `C(get_X)` Low unless cataloged or allowlisted (`Length`/`Count` stay cataloged and constant) |

Sites that stay O(1) because the operation genuinely *is* free are
listed explicitly so the audit is reviewable: unreachable code, a
declarator with no initializer, an empty switch, and an
`ILocalFunctionOperation` **declaration** (cost is paid at the call —
RESEARCH §4.3).

The allowlist is keyed by `(containing type, member, arity)` — the same
identity the catalog already uses — and seeded with `System.Math`,
`System.Convert` on scalars, `System.GC`, scalar `GetHashCode`/`Equals`/
`CompareTo`, `System.Diagnostics`, and the scalar numeric parse/format
members.

- Risk: methods that today report a clean `O(n)` may become `O(n C(f))`
  at Low confidence until 1.2 lands. 1.1 and 1.2 therefore ship in **one
  commit**, and 1.2 is sized to cover the common surface first.
- Several existing expectations may move. Each change is justified in the
  commit message against the rule above; any case where the *new* result
  is worse is a bug in the allowlist, not an argument to restore the
  fallback.

## Phase 2 — Algorithmic cost of the analyzer (S2)

Fixes RESEARCH §3.3. Pure refactor: **no result may change.** Every
phase-2 commit is validated by "full suite green, zero expectation
edits", plus the Phase 0.3 benchmark.

| Step | Change |
|---|---|
| 2.1 | Delete all 7 hand-rolled `Walk`/`WalkAll` iterators; use `operation.Descendants()`. Where a walker deliberately stops at loop boundaries (`LoopBoundInferrer.DirectOps`), keep the pruning but make it an explicit stack-based traversal, not nested `yield return` |
| 2.2 | `CardinalityAnalyzer`: compute the increment-target set **once** into a `HashSet<ISymbol>`; `IsIncremented` becomes a lookup (O(N·W) → O(N)) |
| 2.3 | Memoize loop bounds per `IOperation` in `AnalysisState` so `LoopBoundInferrer.Infer` runs once per loop instead of once per visit from `ApplyTree` and once from the main walk |
| 2.4 | `PatternRecognizer`: single traversal; detectors that need sub-tree facts (`UnboundedWorklist`, `IsNetDecrease`, `BranchingRecursion`) consume one pre-computed per-loop summary (grow/shrink counts, visit-writes, recursive-call counts) instead of re-walking |
| 2.5 | `RecurrenceAnalyzer.TrySolve`: materialize descendants once, share across the classifiers |
| 2.6 | Simplify/prune at composition **boundaries** (method, loop, top-level sequence) rather than at every nesting level, keeping output identical — verified by the full suite |

### 2.7 `BindWarnings` cost (RESEARCH §3.4)

Measured at **~35%** of a keystroke pass on the adversarial fixture
(56–74 ms) and 1–3 ms on a clean file — worth fixing, but second to the
walk. `model.GetDiagnostics()` stays the source of truth for
CS0246/CS0234:

- skip it for **selection** requests (the whole-document pass already
  produced the same file-level warnings, and the extension carries them);
- cache per `(document version, text hash)` so an unchanged buffer does
  not re-bind;
- re-measure with 0.3. If the cache is not enough, scope the diagnostics
  by span — **not** drop the warnings, which are load-bearing for the
  "unresolved types ≠ silent O(1)" promise.

Target for the phase as a whole: move the 4–6 ms/function walk, which is
~60% of every pass.

## Phase 5 — Research-backed additions

**Scheduled: 5.1 and 5.4. Not scheduled: 5.2, 5.3.**

### 5.1 — Scheduled: `NonBacktracking` regex earns a real bound

.NET guarantees an O(n) scan for `RegexOptions.NonBacktracking` only.
When the option is provable at the construction site or on
`[GeneratedRegex(…, RegexOptions.NonBacktracking)]`, report a linear
bound in the input length instead of hard-opaque `O(unknown)`; the
pattern is still named. Anything not provably NonBacktracking — including
a `Regex` reaching the call site as a parameter or field whose options
are not visible — stays opaque. Needs a new torture fixture holding both
arms, and `PatternApplicator.IsOpaque`/`PatternRefiner` gain a
regex-specific split rather than a blanket id.

This is the one place the honesty rule points *toward* a tighter bound:
the guarantee is a documented property of the engine, not an inference.

### 5.4 — Scheduled: widen the bench corpus

Add C# cases at the O(n) ↔ O(n log n) ↔ O(n²) boundary that BigO(Bench)
and CodeComplex identify as the dominant confusion, as a new fixture +
theory alongside `LeetCodeBenchTests`. Every translated case is
hand-checked against a known closed form before it is asserted; a case
Ohno cannot justify is recorded as `O(unknown)`, not dropped. No engine
risk — this is a net that makes Phases 1–4 safe to land.

### Not scheduled this pass

| Item | Why deferred |
|---|---|
| 5.2 CFG ranking-function loop bounds | Largest change in the plan; rewrites `LoopBoundInferrer`, which nearly every fixture depends on. Deserves its own pass and its own review once Phases 1–4 have settled the expectations |
| 5.3 `AnalyzerUtilities` PointsTo/ValueContent | New dependency with notable per-analysis cost, against heuristics that currently pass their tests. Revisit only if a measured alias failure justifies it |

## Sequencing and risk

```
Phase 0  ── harness            (blocking; no behaviour change)
   │
Phase 1  ── BCL accuracy       (S1; changes results by design)
   │
Phase 2  ── analyzer cost      (no result may change)
   │
Phase 3  ── robustness         (no result may change except new guards)
   │
Phase 4  ── coverage + UX      (adds results; .slnx self-verifies)
   │
Phase 5  ── 5.1 regex + 5.4 bench corpus (5.2, 5.3 deferred)
```

5.4 may be pulled forward and landed next to Phase 0: it adds coverage
without touching the engine, so it widens the net Phases 1–4 are checked
against.

Phase 1 before Phase 2 on purpose: the catalog work changes expected
outputs, and it is much easier to review a refactor that is required to
change *nothing* once the expectations have settled.

Highest-risk item is 1.1 (polarity flip) because it can move many
results at once; it is gated on the decision below and ships with 1.2.
Lowest-risk immediate wins are 4.1 (`.slnx`) and 2.2 (increment set),
either of which could ship alone.

## Decisions — settled 2026-08-15

1. **O(1) is never a fallback.** An unresolved executable operation costs
   `C(symbol)` at Low confidence; constant time must be positively known
   via an allowlist of language/runtime primitives. Applied in **1.0/1.1**,
   which audits *every* site that currently invents O(1) — not just the
   `System.*` call path that surfaced it.
2. **Always analyze accessors, indexers, and operators.** Surface an
   inline annotation only when the result is nontrivial, unknown, or
   explicitly requested. Applied in **4.2 / 4.2a**.
3. **Phase 5: 5.1 (NonBacktracking regex) and 5.4 (widened bench corpus)
   are scheduled.** 5.2 (CFG ranking functions) and 5.3 (AnalyzerUtilities
   dataflow) are deferred with reasons recorded above.
